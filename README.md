# Явка

Приложение для быстрой отметки посещаемости: кто пришёл, кто опоздал, кто
не пришёл и у кого уважительная причина.

## Возможности

- Список группы и 4 кнопки отметки: «Пришёл», «Непришёл», «Опоздал»,
  «По уважительной».
- «Непришёл» подтверждается вторым нажатием; время пишется только у
  «Опоздал» — оно и уходит в журнал.
- Выбор дня и пары на экране отметки: можно отметить сегодня или задним
  числом (стрелки, календарь), а отметки привязать к паре из расписания
  или ко всему дню.
- В выходные (суббота и воскресенье) отметки недоступны: кнопки отключены,
  навигация по дням перепрыгивает выходные.
- Выборный дизайн в настройках: светлая/тёмная/системная тема и 5 акцентов
  (бирюза, синий, терракота, слива, олива).
- Вкладка «Расписание»: пары по дням недели. Расписание можно вставить
  документом (текст вида «09:00–10:30 Математика, каб. 201» разберётся
  в пары) или составить самому, добавляя пары списком.
- Локальная база данных: преподаватели, предметы и кабинеты. Предмет
  ссылается на преподавателя и кабинет, при создании пары всё выбирается
  селектами, а новые записи добавляются прямо из диалога пары. Вставленный
  документ с расписанием пополняет базу. База переносится файлом:
  экспорт и импорт JSON.
- Отметка посещаемости на каждой паре: из расписания открывается список
  группы, отметки привязаны к конкретной паре, а не ко всему дню.
- Уведомления: когда вы отмечаете студентов на паре, уведомление
  появляется в колокольчике в шапке (на этом устройстве).
- Десктопная раскладка (Windows/Linux/macOS): кнопки отметки слева,
  список группы справа; на Android и web — мобильный вид.
- Отметки сохраняются локально и не теряются при перезапуске.
- Синхронизация с существующей Google Таблицей на Google Диске:
  приложение подстраивается под ваш журнал и ничего в нём не меняет.
- Автосохранение отметок в таблицу (можно отключить).
- Загрузка отметок из таблицы — удобно, если группу отмечали с другого
  устройства.
- Подходит, если пользователь — не владелец таблицы, а её редактор
  (со-владелец): приложение не меняет права доступа, не создаёт и
  не удаляет файлы.

## Запуск

```bash
flutter pub get
flutter run
```

Запуск на устройствах выполняет человек. Тесты и анализатор:

```bash
flutter analyze
flutter test
```

## Дизайн

Дизайн выбирается в приложении: кнопка с палитрой в шапке экрана отметки.

- **Тема** — «Авто» (как в системе), «Светлая» или «Тёмная».
- **Акцент** — пять спокойных палитр: бирюза (по умолчанию), синий,
  терракота, слива, олива.

Выбор сохраняется на устройстве и применяется ко всему интерфейсу. Палитры
нейтральные — дизайн подходит любому старосте.

## Интеграция с Google Диском (Google Таблицы)

Данные хранятся в обычной Google Таблице, которую ведёт человек: приложение
подстраивается под уже существующий журнал и **ничего в нём не меняет** —
не рисует шапки, не объединяет ячейки, не двигает колонки и не создаёт
листы. Оно только ставит отметки в ячейки пар цветом (а при опоздании —
ещё и время).

### 1. Google Cloud Console

1. Создайте проект в [Google Cloud Console](https://console.cloud.google.com/).
2. Включите **Google Sheets API** (APIs & Services → Library).
3. Настройте **OAuth consent screen**:
   - тип приложения — External;
   - добавьте себя (и тех, кто будет пользоваться приложением) в
     **Test users**, пока приложение не прошло проверку Google.
4. Создайте OAuth-клиент (APIs & Services → Credentials):

   | Платформа | Тип клиента | Что нужно |
   |---|---|---|
   | Android, iOS, Linux, Windows | **Desktop app** | Client ID и Client Secret |
   | Web | **Web application** | Client ID и Authorized JavaScript origins |

   Для web добавьте адрес, на котором запущено приложение, например
   `http://localhost:8080`, в **Authorized JavaScript origins**.

### 2. Передача Client ID в приложение

Релизные сборки (Windows, Android, Linux) собираются с **встроенным
OAuth-клиентом**: вход работает сразу — пользователь только нажимает
«Разрешить», ничего регистрировать не нужно. Client ID и Secret
передаются в сборку через секреты GitHub Actions
(`GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_WEB_CLIENT_ID`),
в репозиторий они не попадают.

Для installed-приложений Google прямо разрешает не считать Client Secret
секретом, поэтому вшивать его в релиз безопасно; квоты Sheets API у всех
пользователей общие на один проект.

Свои значения нужны, только если вы хотите собственный проект и квоты —
три варианта:

Вариант А — при сборке/запуске:

```bash
flutter run -d linux \
  --dart-define=GOOGLE_CLIENT_ID=ваш-client-id.apps.googleusercontent.com \
  --dart-define=GOOGLE_CLIENT_SECRET=ваш-client-secret

# web
flutter run -d chrome \
  --dart-define=GOOGLE_WEB_CLIENT_ID=ваш-web-client-id.apps.googleusercontent.com
```

Вариант Б — прямо в приложении: иконка облака в шапке → «Настройки OAuth» →
вставить Client ID/Secret → «Сохранить настройки OAuth». Значения хранятся
локально на устройстве и перекрывают встроенный клиент.

Вариант В — файлом: в разделе Credentials нажмите «Скачать JSON» и в
приложении («Настройки OAuth» → «Загрузить JSON из Google Cloud Console»)
выберите его. Client ID и Secret подставятся сами: файл типа
«Desktop app» заполнит Client ID/Secret, файл типа «Web application» —
Web Client ID. Ключ сервисного аккаунта для входа не подходит —
приложение сообщит об этом отдельно.

### 3. Подключение таблицы

1. Нажмите иконку облака в шапке.
2. Войдите через Google.
3. Вставьте ссылку на **существующую** таблицу с журналом. Приложение не
   создаёт таблицы — журнал у вас уже есть.
4. Настройте журнал: приложение расспросит и проверит таблицу
   (см. «Настройка журнала» ниже).
5. Поставьте отметки — они отправятся в таблицу автоматически.

Месяц подбирается сам из названия таблицы «МЕСЯЦ : ГОД» (например
`НОЯБРЬ : 2026`). Когда начинается новый месяц, просто вставьте ссылку
на новую таблицу — настройки журнала сохранятся, а месяц сменится сам.

Если таблица принадлежит другому человеку, попросите у него доступ
**«Редактор»** и вставьте ссылку на таблицу. Владельцем останется он —
приложению достаточно прав редактора.

### Настройка журнала

Один раз объясните приложению, где что находится в вашей таблице — экран
«Google Диск» → «Настроить журнал». Вопросы:

1. **Лист журнала** — какой лист таблицы это журнал (например
   `НОЯБРЬ : 2026`).
2. **Строка с числами дней** — строка, где идут числа 1, 2, 3… слева
   направо.
3. **Колонка ФИО** — буква колонки со списком группы (например `B`).
4. **Строка первого студента** — первая строка списка группы.
5. **Строка с номерами пар** — строка «ПАРА», где под числами дней идут
   номера пар (1, 2, 3…). По ней приложение понимает, какая колонка
   какой паре отвечает, а без расписания берёт номера пар из таблицы.
6. **Конечная строка студентов** — последняя строка списка группы (необязательно:
   пусто — студенты читаются до конца листа). Строки ниже списка,
   например «Итого», в список не попадут.

После ответов приложение снимает раскладку журнала: блок колонок каждого
дня — от его числа до следующего числа, поэтому в один день блок может
быть из 2 колонок, в другой — из 3. Журнал может начинаться не с 1 числа
и содержать обрывки — дни без колонок пар или с отрезанным блоком:
такие дни пропускаются, приложение сообщит, что в данный день нельзя
расставить посещаемость. Количество пар в дне берётся из расписания
приложения, а если расписания нет — из строки пар таблицы. Проверка
целостности покажет таблицу день за днём: какие колонки нашлись и
влезают ли пары, а обрывки покажет предупреждениями, не блокируя
синхронизацию по остальным дням.

### Если Google отвечает ошибкой «403»

Google возвращает `403` по разным причинам, и приложение различает их:

1. **«Google Sheets API не включён для вашего OAuth-клиента»** — самая
   частая причина, когда пользователь — редактор. Включите **Google Sheets
   API** в том проекте Google Cloud Console, где создан Client ID
   (APIs & Services → Library), и подождите несколько минут.
2. **«Не хватает доступа „Редактор“ к таблице»** — проверьте два пункта:
   - владелец выдал вам доступ **«Редактор»** (со-владелец), а не
     «Читатель»: откройте «Настройки доступа» таблицы и проверьте роль
     у вашего почтового адреса;
   - войдите в приложение под **тем же Google-аккаунтом**, которому
     выдали доступ: Google проверяет вход, а не ссылку из браузера.
     Выйдите и войдите заново, выбрав нужный аккаунт.
3. **«Google временно отклоняет запросы»** — превышен лимит API,
   подождите пару минут и повторите.

### Как журнал понимается приложением

Раскладка снимается с вашей таблицы по настройке, поэтому журналы могут
отличаться: у любого дня своё число колонок-пар. Семантика такая:

- **колонками пар дня** считаются колонки блока, у которых в строке
  «ПАРА» стоит число; если строка пар не задана, пары нумеруются по
  колонкам блока слева направо (первая колонка — пара 1). Колонка без
  номера в строке пар — не пара: это колонка «на весь день» или пустое
  место за блоком;
- **пара N живёт в колонке с номером N**: если в строке пар колонка
  помечена числом 2, отметки второй пары ставятся в неё, где бы она
  ни находилась внутри блока;
- **отметка на весь день раскладывается на все пары дня**: «пришёл»
  красит каждую колонку пары, «опоздал» — ещё и пишет в них время;
  отдельно отмеченная пара важнее общей отметки и не затирается;
- **пары в дне берутся из расписания приложения**, а если расписания
  нет — номера пар берутся из строки «ПАРА» таблицы;
- **время пишется только у «опоздал»**: «пришёл» и «не пришёл» — это
  только заливка ячейки (и буква «Н» у отсутствия), без времени;
- **выходных (суббота и воскресенье) в таблице не нужно и не
  проверяется**: отметки в выходные запрещены, значит и колонок под них
  в журнале нет; отметки, оставшиеся с прежних версий за выходные, при
  отправке пропускаются молча, без предупреждения;
- **журнал может начинаться не с 1 числа и содержать обрывки** — дни
  без колонок пар или с отрезанным блоком: такие дни пропускаются,
  приложение сообщит, что в данный день нельзя расставить
  посещаемость.

Отметка держится в заливке ячейки:

| Отметка | Заливка | Текст в ячейке |
|---|---|---|
| Пришёл | зелёная `#00FF00` | — |
| Опоздал | оранжевая `#FF9900` | время отметки, например `8:30` |
| Не пришёл | красная `#FF0000` | `Н` |
| По уважительной | синяя `#4472C4` | — |

Лист можно править вручную: приложение разбирает заливку, а для опозданий —
время (`8:30`, `8.30` и почерк `8:3` = 8:30). Чужие пометки на листе не
затираются: при отправке обновляются только ячейки с нашими заливками.
Студентов приложение в таблицу не добавляет: если кого-то нет в колонке
ФИО, синхронизация остановится с подсказкой — допишите студента в таблицу
вручную. Обратно — список группы в приложении подстраивается под журнал:
при загрузке студенты, которых нет в диапазоне строк (например, строка
«Итого»), удаляются из списка вместе со своими отметками.

При загрузке отметок из журнала данные приложения приоритетнее табличных.
Студент, отмеченный в приложении, из таблицы ничего не получает: отметка
на весь день закрывает день целиком (она и записывается в таблицу как
отметки на все пары), отметка на отдельной паре закрывает свою пару.
Таблица только дополняет пробелы — приносит отметки тех студентов и пар,
которых в приложении за этот день ещё нет.

### Уведомления

Уведомления о отметках на парах — локальные: колокольчик в шапке показывает
их на этом устройстве. В таблицу приложение ничего, кроме отметок, не
пишет.

### Ограничения и безопасность

- Приложение использует только scope
  `https://www.googleapis.com/auth/spreadsheets`. Отдельный доступ к
  Google Диску не запрашивается.
- OAuth-токены сохраняются в `SharedPreferences`. Для production-сборки
  лучше заменить хранилище на `flutter_secure_storage`.
- Client Secret установленного приложения не является секретом по
  документации Google, но не публикуйте его без необходимости.
- На web refresh token не выдаётся: при истечении токена нужно войти снова.
- Приложение не удаляет таблицу и не меняет права доступа. Если у
  пользователя нет прав редактора, Google вернёт ошибку 403 — приложение
  покажет понятное сообщение. Если Google отвечает 403 и при правах
  редактора, см. раздел «Если Google отвечает ошибкой „403“» выше.

## Структура

```
lib/
  data/                  локальное хранилище, настройки, контроллеры отметок,
                         расписания, базы (преподаватели, предметы,
                         кабинеты) и уведомлений, парсер документов
  models/                студент, статус, отметка, сессия дня,
                         пара расписания, база, уведомление
  screens/               отметка, расписание, база данных, уведомления,
                         дизайн, экран Google Диска и настройка журнала
  services/cloud/        OAuth, Google Sheets API, адаптация к журналу
                         (месяц из названия, раскладка, проверка, отметки)
  theme/                 нейтральная тема Material 3 и выбор акцента
test/                    тесты логики отметок, расписания и синхронизации
```
